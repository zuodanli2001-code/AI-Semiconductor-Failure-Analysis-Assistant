
# AI Semiconductor Failure Analysis Assistant
# AI 半导体失效分析助手

基于 RAG、Tool Calling 和 Supervisor Agent 的 AI 辅助失效分析原型，实现 SEM 图像基础特征提取、可靠性测试数据分析、本地技术知识检索、AI 辅助分析与报告生成。

## 1. 项目简介

半导体器件及相关光电器件的可靠性分析通常需要综合分析显微图像、性能测试数据和技术文献。传统分析过程依赖人工查阅资料、整理实验数据和编写报告，信息整合过程较为繁琐。

本项目尝试将计算机视觉、数据分析、检索增强生成（RAG）和大语言模型工具调用结合起来，构建一个可交互的 AI 辅助分析系统。

用户可以上传 SEM 图像、可靠性测试 CSV 数据，或针对本地技术文档提出问题。系统根据输入内容调用相应工具，整合检索结果与分析信息，并生成结构化分析报告。

**项目定位：** AI 辅助分析原型，用于技术信息检索、数据整理、候选机理分析与验证方案建议，不替代专业工程师的实验判断。

## 2. 核心功能

| 功能模块 | 实现内容 | 使用技术 |
|---|---|---|
| SEM 图像分析 | 提取图像尺寸、灰度统计、边缘比例等基础特征 | OpenCV、NumPy |
| 可靠性数据分析 | 读取 CSV、预览数据、检查缺失值、分析数值列并绘图 | Pandas、NumPy、Matplotlib |
| 本地知识库检索 | 读取 PDF、TXT、Markdown 文档，进行文本切片、向量化与相似度检索 | RAG、Sentence Transformers |
| AI Agent 分析 | 根据用户问题选择工具，整合工具返回结果并组织回答 | DeepSeek API、Tool Calling、Supervisor Agent |
| 结果验证 | 检查分析结果是否包含必要内容，并提示部分潜在问题 | 自定义校验逻辑 |
| 报告生成 | 整理分析结论、检索来源、证据、局限性及验证建议 | Markdown、JSON |

## 3. 系统架构

```text
                   用户输入
                      |
           +----------+----------+
           |          |          |
        SEM 图像   CSV 数据   技术问题/文档
           |          |          |
           v          v          v
       SEM 分析    数据分析    本地 RAG 检索
           |          |          |
           +----------+----------+
                      |
                      v
              Supervisor Agent
                      |
             DeepSeek Tool Calling
                      |
             调用工具并整合结果
                      |
                      v
              结果验证与证据整理
                      |
                      v
               结构化分析报告
                      |
                      v
              Streamlit 交互界面
```

### 核心设计思路

- **工具与大模型分工：** 图像特征提取和数据统计由程序执行；大模型负责理解问题、决定是否调用工具、整合结果和生成自然语言解释。
- **RAG 优先检索本地资料：** 回答技术问题时，先从本地知识库中检索相关内容，为分析提供可追溯的资料依据。
- **区分证据与推测：** 将知识库直接支持的内容、候选失效机理、尚待验证的假设分开呈现。
- **保留分析局限：** 未提供相关数据或图像时，不将其描述为已经完成分析；缺少直接证据时，不将候选机理写成确定的失效根因。

## 4. 技术栈

- **开发语言：** Python

## 5. RAG 知识检索模块

本项目使用本地技术文档构建轻量级知识检索流程。

### 5.1 文档处理

1. 读取本地 PDF、TXT 和 Markdown 文件。
2. 提取文档文本。
3. 将长文本切分为多个较小的文本块。
4. 设置相邻文本块之间的重叠区域，减少切片边界造成的上下文信息丢失。

当前切片策略使用约 150 个字符的重叠区域。重叠长度是文本切片参数，并不代表整个文本块只有 150 个字符。

### 5.2 文本向量化

使用 `BAAI/bge-small-zh-v1.5` 将文本块转换为语义向量，使系统能够根据文本含义匹配相关内容，而不仅仅依赖关键词是否完全一致。

### 5.3 检索流程

```text
用户问题
   |
   v
问题向量化
   |
   v
与知识库文本向量计算相似度
   |
   v
选取 Top-K 相关文本块
   |
   v
返回文本内容与来源信息
   |
   v
交由 Agent 结合问题组织回答
```

### 5.4 检索评估

项目曾使用 10 个测试问题、共 50 个检索结果进行初步评估：

| 指标 | 测试结果 |
|---|---:|
| Precision@5 | 0.40 |
| MRR | 0.80 |
| Hit@5 | 1.00 |

指标含义：

- **Precision@5：** 每个问题返回前 5 条结果中，相关结果所占比例的平均值。
- **MRR：** 根据第一个相关结果的排名评价检索质量，排名越靠前，得分越高。
- **Hit@5：** 测试问题的前 5 条结果中至少出现一条相关内容的比例。

以上是当前测试集上的初步结果，并不代表系统在所有技术问题上的检索表现。随着测试集扩大，还需要进一步评估不同文档类型、问题难度及检索参数对结果的影响。

## 6. Agent 与 Tool Calling

本项目采用 Supervisor Agent 思路组织分析流程。

大语言模型根据用户的问题判断需要执行的操作，并通过 Tool Calling 调用相应的分析工具。工具执行完成后，Agent 根据返回结果生成解释和建议。

典型流程：

1. 接收用户的自然语言问题及可选文件。
2. 判断是否需要调用 SEM 分析、可靠性数据分析或 RAG 检索工具。
3. 执行工具并获取结构化结果。
4. 结合工具结果与知识库证据生成回答。
5. 检查输出内容，并生成结构化分析报告。

其中，工具调用是模型请求执行某项预先定义的功能的机制，并不意味着模型本身具备图像测量、数据统计或独立验证实验结论的能力。

## 7. 可靠性分析思路

系统面向高温、高湿、温度循环等常见可靠性测试场景，可辅助整理测试数据、对比老化前后性能变化，并结合本地资料提出候选失效机理和验证建议。

分析过程强调以下逻辑：

**测试条件 → 观测到的变化 → 直接证据 → 候选机理 → 验证方案**

例如，针对 85°C/85%RH 高温高湿测试，可以先比较老化前后的发光性能或其他已有性能指标，再结合图像形貌及材料分析结果讨论可能的水汽侵入、界面变化或材料老化等问题。

这些机理只能作为待验证的候选解释。具体根因需要由实际测试结果、对照实验和进一步表征共同支持。

## 9. 环境配置与运行

### 9.1 环境要求

- Python
- Visual Studio Code 或其他 Python 开发环境
- 可用的 DeepSeek API Key
- 可访问模型下载源或已经下载好的本地文本向量模型

### 9.2 安装依赖

进入项目根目录，在终端执行：

```bash
pip install -r requirements.txt
```

如果项目还没有 `requirements.txt`，需要根据当前实际使用的 Python 包整理依赖后再执行。

### 9.3 配置环境变量

在项目根目录创建 `.env` 文件，填写：

```dotenv
DEEPSEEK_API_KEY=你的_DEEPSEEK_API_KEY
DEEPSEEK_MODEL=deepseek-chat
```

请替换为自己的 API Key。不要将真实密钥直接写入源代码，也不要将 `.env` 提交到公开代码仓库。

### 9.4 启动应用

在项目根目录的 VS Code 终端中执行：

```bash
streamlit run app.py
```

随后在浏览器中打开 Streamlit 提供的本地访问地址。

## 10. 测试与验证

项目已围绕核心功能开展测试，重点包括：

- SEM 图像是否能够正常上传并返回基础特征。
- CSV 文件是否能够读取并完成预览、缺失值检查和数值分析。
- RAG 是否能够检索本地文档并显示相关内容及来源。
- Agent 是否能够根据问题调用相应工具并整合结果。
- 综合分析是否能够区分直接证据、候选机理、局限和验证建议。
- 报告是否能够正常生成和导出。

实际测试结果应以当前运行版本为准。程序内部的校验通过，仅说明输出满足设定的检查条件，不等同于所有分析结论已经得到独立实验验证。

## 11. 当前局限与后续方向

### 当前局限

1. **SEM 分析：** 目前主要提取灰度、边缘等基础图像特征，尚未实现经过标注数据训练和验证的自动缺陷分类模型。
2. **根因诊断：** 候选失效机理依赖现有数据、知识库内容和模型推理，不能直接视为经过验证的根因结论。
3. **知识库覆盖：** 检索结果受本地文档质量、覆盖范围、切片方式和检索参数影响。
4. **结果验证：** 现有校验主要针对输出结构与必要信息，不能代替材料表征、失效复现和对照实验。
5. **工程化程度：** 当前定位为个人开发的功能原型，仍需要更系统的测试、日志管理和真实案例验证。

### 后续改进方向

- 扩充并整理高质量的材料、器件和可靠性技术知识库。
- 建立更系统的 RAG 测试集，优化检索效果。
- 完善工具调用日志、异常处理和结果可追溯性。
- 在获得可靠标注数据后，探索 SEM 缺陷识别与图像分析模型。
- 通过真实案例和对照实验评估候选机理分析的有效性。

## 12. 项目总结

本项目完成了一个结合本地图像分析、可靠性数据处理、RAG 知识检索和大语言模型工具调用的 AI 辅助失效分析原型。

项目重点不在于让大模型直接给出未经验证的失效结论，而是通过工具执行、资料检索、证据整理和结构化报告，探索如何将大语言模型应用于工程分析工作流。
